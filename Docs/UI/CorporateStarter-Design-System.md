# CorporateStarter — Design System

> **Это единственный источник правды по дизайну CorporateStarter.**
> Заменяет и отменяет `CorporateStarter-MudBlazor-UI-Design-Rules.md` и `Interaction Patterns.md` — оба удалены, их содержимое либо вошло сюда, либо было сознательно отклонено как не соответствующее решённому направлению.

Позиционирование: профессиональный, сдержанный enterprise-инструмент для операторов (аналог по духу — Retool/Stripe/Linear/IBM Carbon, не Material/consumer-приложения). Приоритет — скорость сканирования, предсказуемость, минимум когнитивной нагрузки.

Целевые устройства: **desktop (основной), планшет, телефон** — интерфейс должен адаптироваться на всех трёх, см. раздел 7.

Живой макет-песочница (HTML) со всеми паттернами существует отдельно от кода и используется только как визуальный референс на этапе проектирования.

---

## 1. Цвета

Правило: **не плодить цвета без доказанной семантической необходимости.** Это не железный запрет навсегда — если домен-специфичный статус (например, результат теста: passed/failed/pending, или статус калибровки) объективно требует различения sever случаев цветом, точечно вводится нужный цвет именно под этот статус. Что запрещено — заводить warning/success/info как цвета общего назначения для кнопок, навигации, тулбара "про запас".

Базовые (действуют везде):

| Токен | HEX | Назначение |
|---|---|---|
| `Primary` (blue) | `#2883EE` | Кнопки, заголовок грида, активные состояния, ссылки |
| `PrimaryDarken` | `#1A6BD1` | Hover/pressed для primary |
| `White` | `#FFFFFF` | Фон, поверхности |
| `TextPrimary` | `#1E293B` | Текст, монохромные иконки |
| `Error` | `#DC2626` | Удаление, невалидные поля, критичные баннеры/toast |
| `ErrorDarken` | `#B91C1C` | Hover для error-кнопок |

Производные (тени базовых, не самостоятельные цвета):

| Токен | Значение | Назначение |
|---|---|---|
| `Divider` | `rgba(30,41,59,.12)` | Обычные границы/разделители |
| `LinesInputs` | `rgba(30,41,59,.22)` | Границы инпутов |
| `TextSecondary` | `rgba(30,41,59,.6)` | Второстепенный текст, подписи |
| `PrimaryTint` | `rgba(40,131,238,.08)` | Hover-фон строк, info-баннер |
| `PrimaryTintStrong` | `rgba(40,131,238,.14)` | Фон выбранной строки/активного пункта меню |
| `ErrorTint` | `rgba(220,38,38,.08)` | Фон critical-баннера, иконка в confirm-диалоге |

**Резерв на будущее (не создавать заранее, только когда появится конкретный кейс):** `Warning`, `Success` — вводятся исключительно под конкретный домен-статус (например, результаты тестов приборов), никогда как повторно используемые UI-цвета кнопок/навигации.

## 2. Типографика

Шрифт: **Inter** (фолбэк: Segoe UI, Roboto, sans-serif).

Базовый размер: **16px**.

| Уровень | Размер | Вес | Назначение |
|---|---|---|---|
| H1 | 24px | 600 | Заголовок страницы |
| H2 | 18px | 600 | Заголовок панели/диалога/sidesheet |
| Body | 16px | 400 | Основной текст, значения полей |
| Small | 14.5px | 400 | Подписи, содержимое грида |
| Caption | 13px | 400 | Счётчики, метаданные |

---

## 3. Сетка, отступы, скругления

- Базовая сетка отступов: **8px** (4/8/12/16/24/32/48).
- Скругления: **6px** везде (кнопки, инпуты, карточки, попапы).
- Тени: `sm` (грид/карточки), `md` (sidesheet/popover/dropdown), `lg` (модальные диалоги).

Эстетический референс: IBM Carbon Design System — ближе по духу, чем Material, для data-dense enterprise-продуктов.

## 4. Component API

Контракт параметров для переиспользуемых компонентов. Экран не должен изобретать свой вариант тулбара/формы — только комбинировать эти компоненты.

### `CsStatusText`
| Параметр | Тип | Обязательный | Описание |
|---|---|---|---|
| `IsActive` | bool | да | true → текст цвета Primary, false → TextSecondary |

### `CsTabs` / `CsTabPanel`
| Параметр | Тип | Обязательный | Описание |
|---|---|---|---|

Единая точка вызова — не использовать `ISnackbar` напрямую в компонентах страниц.

| Метод | Назначение |
|---|---|
| `CsToast.Success(message)` | Обычное подтверждение |

| `CsToast.Conflict(message, onRefresh)` | С кнопкой "Обновить" (конфликт одновременного редактирования) |

| `Message` | string | да | |

## 5. Навигация, топбар, грид — поведенческие паттерны

### Drawer
- Expanded (250px) — `MudNavMenu`/`MudNavGroup`, клик разворачивает подпункты inline (аккордеон)
- Collapsed (64px, icon rail) — `MudDrawer` mini-режим с hover-раскрытием подменю (нативная возможность MudBlazor — `Variant="Mini"` + `OpenMiniOnHover`, не кастомный CSS)
- Иконки разделов — монохромные, цвет текста по умолчанию, Primary для активного пункта
- Длинные списки подпунктов (20+) — добавляется поиск/фильтр сверху списка

### Топбар
- Светлый фон, высота 58px
- Гамбургер слева — переключатель drawer
- Индикатор организации/точки обслуживания — рядом с заголовком
- Колокольчик уведомлений с бейджем: одно сообщение — клик открывает его прямо в popover; несколько — список
- Пользователь — крайний правый элемент

### Toolbar грида
Белые кнопки, синий ободок и синяя иконка, в ряд: Add, Edit (активна только при ровно 1 выбранной строке), Delete (активна при ≥1), Refresh, "⋯" (Export CSV/Excel). Find — справа, отдельно от глобального поиска на уровне `CsPageHeader`.

### Грид
- `MudDataGrid`, compact density
- Заголовок — Primary-заливка, белый текст; сортировка + фильтр в каждой ячейке заголовка
- **Выбор строк без чекбоксов**: клик — выбрать одну; Ctrl/Cmd+клик — добавить к выделению; Shift+клик — диапазон
- "Выбрать все" сознательно не реализуется, пока не появится реальный сценарий массовых операций
- Пустое состояние, скелетон-загрузка при первичной загрузке (не спиннер поверх грида)
- Пагинация справа под гридом рядом со счётчиком "X–Y of Z items"

## 6. Состояния данных

| Состояние | Где показывается | Правило |
|---|---|---|
| **Loading** | Грид при первой загрузке | Skeleton-строки (shimmer на тенях `Divider`/`PrimaryTint`), не спиннер |
| **Loading (действие)** | Кнопка Save/Submit | Кнопка переходит в `is-loading`: спиннер + приглушённый текст, disabled на время запроса |
| **Empty** | Грид без результатов (фильтр/поиск ничего не нашёл) | Иконка + "Ничего не найдено" + подсказка сбросить фильтры |
| **Error (загрузка)** | Грид не смог загрузиться | Иконка + текст ошибки + кнопка "Повторить" (не путать с Empty) |
| **Error (валидация)** | `CsFormField` | Красная рамка + текст под полем с иконкой |
| **No permission** | Действие/страница недоступны роли пользователя | Кнопка/пункт меню не показывается вообще (не просто disabled) — если весь раздел недоступен, страница показывает нейтральный `CsBanner` (`Info`) "Недостаточно прав для просмотра" вместо контента |
| **Stale / conflict** | Запись изменена другим пользователем пока sidesheet был открыт | `CsToast.Conflict` с кнопкой "Обновить" — не блокирующий модал |
| **Unsaved changes** | Закрытие `CsEditDrawer` с `IsDirty=true` | Блокирующий `CsConfirmDialog` (`IsDestructive=false`, кнопка "Discard" не красная — ничего не удаляется из системы, теряется только черновик правки). Toast здесь не используется: в отличие от undo-delete, непрочитанный toast означал бы безвозвратную потерю ещё не отправленного ввода, а не обратимое действие |

## 7. Responsive

Три целевых класса устройств:

| Брейкпоинт | Устройство | Поведение |
|---|---|---|
| `> 1280px` | Desktop | Полный вид: expanded/collapsed drawer, sidesheet 380px рядом с гридом, грид с горизонтальным скроллом при необходимости |
| `768–1280px` | Планшет (landscape) | Drawer по умолчанию collapsed (icon rail), sidesheet становится full-screen overlay поверх грида вместо панели сбоку |
| `< 768px` | Телефон | Drawer — полноэкранный overlay, скрыт по умолчанию, открывается по гамбургеру и закрывается после выбора пункта; **грид по умолчанию превращается в карточный список** (по одной записи на карточку) для обычных сущностей — горизонтальный скролл оставляем только для технических/широких таблиц, где карточный вид потерял бы табличную структуру данных; toolbar сворачивает второстепенные действия (Refresh/More) в один "⋯" |

`CsEditDrawer` сам переключает Anchor/полноэкранность по текущему брейкпоинту — вызывающий код не должен об этом думать.

## 8. Accessibility

- Все icon-only элементы (`CsGridToolbar`, кнопки sidesheet, bell, hamburger) обязаны иметь `aria-label` — тултип не заменяет это для screen reader
- Фокус должен быть видимым отдельно от hover: клавиатурный `:focus-visible` — заметная обводка (Primary), не совпадающая по стилю с обычным hover-состоянием
- `CsEditDrawer`, `CsConfirmDialog` — focus trap: Tab не выходит за пределы открытой панели, `Escape` закрывает панель/диалог
- Грид — базовая клавиатурная навигация (стрелки между строками, Enter открывает запись — эквивалент double-click)
- Порядок Tab должен соответствовать визуальному порядку (актуально при флексе toolbar/footer)

## 9. MudBlazor — техническое соответствие

| Паттерн | Компонент MudBlazor |
|---|---|
| Drawer (expanded/accordion) | `MudDrawer` + `MudNavMenu` (`MudNavGroup`/`MudNavLink`) |
| Drawer (collapsed/hover-flyout) | `MudDrawer Variant="Mini" OpenMiniOnHover="true"` |
| Sidesheet | `MudDrawer Anchor="Right"` (не `MudDialog`) — с адаптацией под §7 на планшете/телефоне |
| Грид | `MudDataGrid`, compact density, кастомный обработчик кликов под Ctrl/Shift-мультиселект |
| Confirm-диалог | `MudDialog` с кастомной разметкой (не стандартный `ShowMessageBox`) |
| Toast | `ISnackbar`, обёрнутый в `CsToast` (см. §4) |
| Тултипы | `MudTooltip` + явный `aria-label` на исходном элементе |
| Tabs | `MudTabs` |

## 10. Форма логина

Полноэкранная страница (не диалог/оверлей) — до входа "приложения под ней" ещё не существует, накрывать нечем:
- Левая панель (~44% ширины, мин. 360px) — Primary-градиент, название продукта, короткий слоган, декоративная геометрия без насыщенной графики
- Правая часть — белая, центрированная форма: заголовок, поля Логин/Пароль (единый стиль инпутов, включая `type="password"`), чекбокс "Запомнить меня", ссылка "Забыли пароль?", кнопка "Войти" на всю ширину формы
- На телефоне (`< 768px`) — брендовая панель скрывается или сворачивается в узкую полосу сверху, форма занимает весь экран

## 11. Архитектура (Server + WASM)

CorporateStarter — темплейт для запуска и как Blazor Server (малые команды), и как Blazor WebAssembly (крупные команды), из одной кодовой базы:

```
CorporateStarter.UI/          ← Razor Class Library: MudTheme, все Cs*-компоненты, layout
CorporateStarter.Web/         ← текущий host (уточнить целевую модель рендеринга)
CorporateStarter.Wasm/        ← (план) второй host под WASM, ссылается на CorporateStarter.UI
CorporateStarter.Api/         ← существующий API
```

Компоненты и тема пишутся один раз в `CorporateStarter.UI`, хосты — тонкие точки входа. Отличия Server/WASM (аутентификация: cookie vs token, `IJSRuntime`-специфика, `PersistentComponentState`) инкапсулируются в сервис-абстракции, не в самих UI-компонентах.

Порядок имеет значение — каждый следующий зависит от предыдущих:

3. `CsPageHeader`
4. `CsGridToolbar`
5. `CsStatusText`
6. `CsFormField`
7. `CsEditDrawer`
8. `CsConfirmDialog` (включая non-destructive вариант для unsaved changes)
9. `CsToast` (обёртка над `ISnackbar`)
10. `CsBanner`
11. `CsTabs` / `CsTabPanel`

Дизайн-система остаётся бумажной, пока не собран этот список — активная разработка клиентских экранов начинается после него, не параллельно с ним.

## 13. Definition of Done для CRUD-экрана

Экран сущности (список + форма) считается завершённым, когда пройдены все пункты:

- [ ] Список: loading (skeleton), данные, empty, error-состояние с "Повторить"
- [ ] Grid selection: одиночный клик, Ctrl/Cmd+клик, Shift+клик — работают корректно
- [ ] Toolbar: Add/Edit/Delete корректно включаются-выключаются от состояния выделения
- [ ] Add — открывает `CsEditDrawer` в пустом состоянии
- [ ] Edit — по кнопке и по double-click на строке, открывает с заполненными данными
- [ ] Delete — через `CsConfirmDialog` (destructive), успешное удаление даёт `CsToast.Undo`
- [ ] Валидация — обязательные поля помечены звёздочкой до отправки; ошибки показываются через `CsFormField.ErrorText`
- [ ] Save — кнопка уходит в loading, по успеху `CsToast.Success` и закрытие drawer, по ошибке `CsToast.Error` и drawer остаётся открытым
- [ ] Закрытие drawer с несохранёнными изменениями — non-destructive `CsConfirmDialog`
- [ ] Permission-кейс — если применимо, недоступные действия скрыты, не просто disabled
- [ ] Responsive — экран проверен на desktop/tablet/phone брейкпоинтах из §7
- [ ] Accessibility — icon-only кнопки имеют `aria-label`, drawer/dialog проверены на focus trap и `Escape`

## 14. Эталонный экран

Первый реализуемый экран — `AreasPage.razor` (простейшая сущность из референса: Name, MeterShop, Operating Area, Active). Его задача — не про "область", а про то, чтобы зафиксировать **архитектурный паттерн**, который потом переносится на остальные сущности через копирование структуры, а не переизобретение. Дизайн-система считается рабочей (не бумажной) только после того, как `AreasPage` пройдёт весь чеклист §13.
